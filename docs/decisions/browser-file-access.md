# 文件打开优先使用网页

日期：2026-10-19。适用：WSL Ubuntu 后端、Windows 浏览器的本地维护分支。

用户环境要求日常工具可从网页或 Windows 使用。源码观察表明原实现依赖 Electron 打开目标服务；已有未提交改动用 `wslpath` 和 Explorer 桥接，但进程启动成功只能说明 Explorer 被启动，不能证明目标文件已被关联应用打开。浏览器 `file://` 也不能直接读取服务端 Linux 文件。

采用 HTTP 文件查看与下载作为主要操作路径：在 openIn 服务解析本地 cwd 和路径后，将文件事件发回所属 view，浏览器在当前标签页弹出预览；文件页由 WSL 服务读取内容。文件管理器动作转目录浏览。保留既有 Windows Explorer 回退，避免修改不属于本次工作的已有实现。

取舍：网页可覆盖文本、图片、媒体、PDF 与目录，免除大多数跨系统路径和应用关联问题；Office 等格式先下载后用 Windows 工具打开，不增加第三方在线转换、编辑器或本机应用自动控制。代码侧栏和远程主机文件继续沿用上游能力。

不采用全面修复 Windows 文件关联作为主要方案：用户允许两条路径任选，这条路径需要逐个应用验证 UNC 和 WSL 支持，且无法服务其他远程浏览器。后续只有明确需要特定 Windows 应用直接编辑原文件时，再设计显式应用桥接。

实现入口与接口见 [文件访问手册](../file-access.md)，验证依据见 [验证记录](../validation.md)。
