# 首屏功能配置缓存

当前实现：`src/browser/startup-cache.ts`，通过 `webview-startup-cache.patch` 接入上游 bootstrap 初始化，补丁由 `scripts/prepare_asar` 应用。浏览器构建后刷新生效，无需重启服务。

## 缓存位置与身份校验

配置保存在当前网站 origin 的浏览器 IndexedDB（`codex-web-startup`，`bootstrap` store）。这是浏览器持久缓存，不是本地服务共享的全局响应缓存；不同浏览器、浏览器 profile 和 origin 各自建立缓存。首次没有成功配置时仍需联网。

正文约 7.1 MB，未使用容量较小的 localStorage。只保留一条 bootstrap 配置，记录保存时间及 scope 的 SHA-256，不保存输入认证令牌，也不将配置正文写入服务日志。IndexedDB 不可用、配额不足或读取超过 500 ms 时，保留原网络启动路径；写入失败可在当前页面内存复用，不能承诺跨刷新持久命中。

每次初始化先通过现有 `accessInputs.readAccountInfo(true)` 从本地宿主读取已认证用户、账户/工作区 ID。这条本地 RPC 从认证令牌提取身份，不是向官方重新下载功能配置。前端短暂的邮箱快照不用于缓存键。缓存 scope 包含用户、账户、已认证用户别名、SDK key、应用版本、build flavor、beta、语言、stable ID、系统信息、plan 和计算区域；不包含每次变化的 app session ID。返回配置中的用户与账户必须匹配本地已验证身份，才允许缓存。

观察到退出登录或切换账户时清除缓存，代次检查阻止旧请求迟到后写回。不同工作区、版本或其他 scope 不匹配时按未命中处理。缓存仅用于功能配置，不替代认证或服务端权限校验。

## 有效期与刷新

| 配置年龄 | 首屏行为 | 额外 bootstrap 请求 |
| --- | --- | --- |
| 0–10 分钟 | 直接从缓存同步初始化 SDK | 不主动重新下载整份 bootstrap |
| 10 分钟–1 小时 | 先从缓存启动 | 首屏后尝试后台刷新一次，供后续导航使用 |
| 超过 1 小时、损坏或上下文不匹配 | 保留原联网初始化 | 当前页面等待原请求/原回退路径 |

后台刷新等待首屏信号，最长等待 30 秒后可启动；隐藏标签页等到可见再启动。后台再次核对本地身份；响应头预算 4 秒、正文预算 15 秒，普通前台请求仍是 4 秒 + 4 秒。一次刷新失败保留旧条目及原保存时间，不延长有效期，不无限重试。页面内同 scope 请求合并。

无缓存且原请求失败时，原上游备用初始化继续处理；首屏后另外尝试一次有界刷新，为后续打开预热缓存。当前页面的 SDK 仍保留 `enableLiveValuesAutoRefresh` 原有行为；自建缓存的完整 bootstrap 后台刷新只替换持久缓存，不强制重新挂载当前界面。

## 版本号与“脏标记”

内置 Statsig SDK 支持 `time`、`full_checksum`、`sinceTime`、`has_updates` 等版本/增量协议，未改动其实现。它们分别用于配置时间/游标、完整校验值、请求基线和是否有更新；不是本地可凭空知道的官方推送脏标记。

本轮真实 bootstrap 在当前客户端可见的响应中有 `time`，没有看到 ETag、Last-Modified 或 full_checksum。因此没有给这个 POST 接口擅自增加 If-None-Match、GET/HEAD 或未证实的 sinceTime 参数。自建缓存按年龄和上下文判断是否需要整份刷新；SDK 自己的增量检查继续运行。配置中的 `time` 不能单独证明身份和运行上下文也一致，应用版本与账户仍单独参与校验。

## 观测与验证

右下角启动诊断会显示使用缓存、过期或未命中。复制诊断包含缓存命中状态、年龄和可见版本元数据，不包含配置正文。也可读取 `window.__ELECTRON_SHIM__.startupConfigCache.diagnostics`。浏览器关闭后缓存是否保留受浏览器隐私/清理策略约束。

实页首次无缓存导航首屏为 18.160 秒，原前台请求未完成，随后后台刷新成功写入。接下来的三次刷新均命中 fresh 缓存，首屏分别为 5.146 / 3.811 / 3.830 秒，输入框存在，启动 trace 中 bootstrap 请求次数均为 0。首次与后续样本还包含脚本缓存/编译预热差异，不能把总差值全部归因于配置缓存。能直接确认的是：重复打开消除了首屏对整份 bootstrap 网络传输的等待。

将自动化浏览器内的测试条目设为 11 分钟旧后，实页命中 stale 缓存，首屏 4.498 秒；后台刷新在导航约 4.911 秒才开始，约 10.162 秒完成，返回 `time` 较旧条目更新。输入框存在，后台整份刷新没有阻塞首屏。未修改真实用户的浏览器 profile、登录状态或账户设置。20 项 startup 测试、前后端构建、TypeScript、prepare shell/模块语法、补丁反向 dry-run 与 whitespace 检查通过。

最终将已认证计算区域纳入 scope 后，重新等待 IndexedDB 写入完成再刷新，命中 fresh 缓存、首屏 5.094 秒，输入框存在。缓存尚未建立时立即刷新可能中断后台预热，因此首次需要正常取得并保存一次完整响应；不能承诺从未有过缓存的浏览器首次打开就免网络等待。

脚本与测量保留在 `scratch/startup-cache/`，不提交运行产物。`npm run test:startup` 覆盖持久缓存复用、过期、后台刷新、身份/工作区/版本隔离、退出登录、迟到响应、存储故障及原超时边界。
